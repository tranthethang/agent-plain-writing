# English examples: common pairs

Use for every document type, or when no type fits.
Numbers and stories in the examples are illustrations only. In real work, use the author's numbers or write `TBD`.

## 1. Empty opening

**Bad:** In today's fast-paced digital world, effective data management plays a crucial role. Let's dive in!
**Good:** Last week my report took 40 seconds to open. The cause was one table with 200,000 rows.
**Fault:** A generic opening. **Fix:** Open with a concrete event.

## 2. Stuffed sentence

**Bad:** This tool, which was developed in order to assist developers in managing their AI sessions, allows for the saving of history and, at the same time, facilitates seamless handoffs between agents.
**Good:** This tool helps developers manage AI sessions. It saves the history. One agent can pick up where another stopped.
**Fault:** Three ideas in one sentence. **Fix:** One idea per sentence.

## 3. Nominalization and passive voice

**Bad:** Validation of the data is performed prior to its storage.
**Good:** The system validates the data before saving it.
**Fault:** "validation", "is performed", no actor. **Fix:** Name the actor. Use the verb.

## 4. Empty adjectives

**Bad:** The new interface is beautiful, modern and user-friendly.
**Good:** Each screen has one main button. Users don't have to guess what to press.
**Fault:** Evaluative adjectives. **Fix:** A detail you can see.

## 5. Heavy jargon

**Bad:** The system utilizes a caching mechanism in order to optimize data retrieval performance.
**Good:** The system saves results it has already computed. Next time, it answers faster.
**Fault:** Four jargon words in one sentence. **Fix:** Say the result, drop the mechanism.

## 6. Repeated explanation

**Bad:** The app supports synchronization. In other words, data is updated across devices. This means you will see the same data on every device.
**Good:** Edit on your phone. Your computer updates too.
**Fault:** Three sentences, one idea. **Fix:** Keep the most concrete one.

## 7. A list written as prose

**Bad:** The tool does not run the stages, does not schedule agents, does not call the model directly, does not verify the model name and does not read folders from the old version.
**Good:**
- It does not run the stages.
- It does not schedule agents.
- It does not call the model directly.
- It does not verify the model name.
- It does not read folders from the old version.

**Fault:** The reader must scan but is forced to read straight through. **Fix:** Bullets, one item each.

## 8. Filler transition

**Bad:** In addition to that, another issue that is worth noting is error handling.
**Good:** Second issue: error handling.
**Fault:** The transition is longer than the content. **Fix:** A heading or a short phrase.

## 9. Empty closing

**Bad:** In conclusion, I hope this article has provided you with valuable insights. Thank you for reading!
**Good:** Try one thing today: open your project and count the global variables.
**Fault:** Recap and empty thanks. **Fix:** End with one action.

## 10. Numbers instead of feelings

**Bad:** This change makes the system significantly faster.
**Good:** After the fix, processing time dropped from 3 seconds to 200 ms.
**If you have no number:** "Not measured yet. Measure the processing time before and after the fix." Never invent a number.

## 11. Passive voice with no actor

**Bad:** The configuration files will be generated by the system and then subsequently read by each service.
**Good:** The system generates the config files. Each service reads them.

## 12. A fast word turned into an invented number

(The source says only: the new search is fast, and it replaces the old search page.)

**Bad:** The new search returns results in under 200 ms.
**Good:** The new search replaces the old search page.
**Fault:** The number 200 ms is not in the source.
**Fix:** Keep the fact the source gives, or drop the adjective. Add no number.

## Complete sample

```markdown
## Nightly backup schedule

The billing database runs a full backup at 02:00 UTC every day. Snapshots stay on encrypted storage for 30 days before automatic deletion.

A restore from snapshot takes about 12 minutes for a 40 GB volume. During a restore, new writes pause until the volume mounts.

Teams that need a copy outside this window can trigger a manual snapshot from the admin console. Manual snapshots count toward the same 500 GB quota.
```
