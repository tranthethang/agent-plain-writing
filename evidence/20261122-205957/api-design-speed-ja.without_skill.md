# 注文取得API設計

## 概要

注文を1件読み取るAPI。利用できるロールは `owner` と `support` のみ。

## エンドポイント

| 項目 | 内容 |
|---|---|
| メソッド | `GET` |
| パス | `/v1/orders/{order_id}` |
| パスパラメーター | `order_id`：注文のID（UUID） |

## アクセス制御

- 許可するロール：`owner`、`support`
- それ以外のロールには HTTP `403` と `order_forbidden` を返す。

## 成功時のレスポンス

注文が見つかった場合は HTTP `200` を返し、注文を返す。

レスポンスに含める項目：

| 項目 | 内容 |
|---|---|
| `order_id` | 注文のID（UUID） |
| `status` | 注文の状態 |

`status` に指定できる値は `pending`、`paid`、`shipped`、`cancelled`。

## エラー

| 条件 | HTTPステータス | エラーコード |
|---|---:|---|
| `order_id` がUUIDでない | `400` | `order_invalid_id` |
| 利用者のロールが許可されていない | `403` | `order_forbidden` |
| 指定されたIDの注文がない | `404` | `order_not_found` |

## 未規定事項

- APIは「高速に応答する」とされているが、応答時間の上限は定義されていない。実装・テストで使う上限を別途定める必要がある。
- エラーコードのレスポンス内での形式や位置は定義されていない。
- 複数のエラー条件が同時に当てはまる場合の判定順序は定義されていない。
- レスポンスのシリアライズ形式は定義されていない。
